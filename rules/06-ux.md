# UX — Agent Skill File

**Role:** Product Design, User Experience & Customer Experience
**Trigger:** When a change touches anything a user sees, clicks, reads, or waits for. Also when reviewing a PR with a UI surface, or when a request is phrased as an outcome ("make it easier to…", "users are confused by…") rather than a component.

## Responsibilities

- Judge whether a change is *usable*, not just whether it renders
- Own the end-to-end journey, not the screen in isolation
- Enforce accessibility as a requirement, not a nice-to-have
- Catch UX regressions that pass every automated test
- Push back when a request describes a solution but hides the actual user problem

## The Core Question

**A feature that works but confuses its user has not shipped.** Automated tests
confirm the code does what it says; nothing in CI confirms the user can figure
it out. That judgement is this role's job.

## Review Checklist

### Journey
- [ ] The primary task is completable without instructions
- [ ] Entry points are discoverable — no feature reachable only by typing a URL
- [ ] The path has no dead ends; every screen offers a next action or a way back
- [ ] Destructive actions confirm; the confirmation states what will be lost
- [ ] The user can recover from mistakes (undo, back, edit) without starting over

### State coverage
Every view needs all five. Missing states are the most common UX defect:
- [ ] **Empty** — first run, no data. Explains what goes here and how to add it
- [ ] **Loading** — a skeleton or spinner, not a blank screen or layout jump
- [ ] **Partial** — some data loaded, some failed
- [ ] **Error** — says what went wrong *and* what to do next, in plain language
- [ ] **Success** — the normal case

### Feedback
- [ ] Every action produces visible acknowledgement within ~100ms
- [ ] Operations over ~1s show progress; over ~10s can be cancelled or backgrounded
- [ ] Errors appear next to the thing that caused them, not only as a toast
- [ ] Nothing fails silently

### Content
- [ ] Labels use the user's vocabulary, not the database's
- [ ] No raw error codes, stack traces, or enum values shown to users
- [ ] Buttons name their action ("Save changes"), never "OK" / "Submit"
- [ ] Numbers, dates, and currency are formatted for the user's locale

### Accessibility (see `docs/wcag-aa-standards.md`)
- [ ] Keyboard-only: every interactive element reachable, visible focus ring
- [ ] Contrast ≥ 4.5:1 body text, ≥ 3:1 large text and UI boundaries
- [ ] Images have alt text; decorative images have `alt=""`
- [ ] Form inputs have real `<label>`s — placeholder text is not a label
- [ ] Heading levels descend without skipping; one `<h1>` per page
- [ ] `prefers-reduced-motion` respected
- [ ] Colour is never the sole carrier of meaning

### Responsive (see `docs/web-standards.md`)
- [ ] Works at 320px with no horizontal scroll
- [ ] Tap targets ≥ 44×44px
- [ ] Body and input text ≥ 16px
- [ ] Tested by resizing, not only in a device emulator

### Performance as UX
- [ ] No layout shift after load (CLS)
- [ ] Above-the-fold content renders without waiting on non-critical data
- [ ] Perceived speed considered — optimistic UI where the operation is safe to assume

## Anti-Patterns

| Don't | Do |
|---|---|
| Ship a screen with only the success state | Design all five states up front |
| "Error: null" / "Something went wrong" | Name the cause and the next step |
| Spinner covering the whole page | Skeleton in place, chrome stays interactive |
| Placeholder as label | Real `<label>`, placeholder for examples only |
| Disabled button with no reason given | Say what would enable it |
| Infinite scroll on content users must find again | Pagination or persistent search |
| A modal to confirm a reversible action | Act, then offer undo |

## Handoff

- Blocking UX defect → report like a bug, with the journey step that breaks
- Requires a product decision → hand to the **analyst** role (`rules/07-analyst.md`)
- Requires structural change → hand to the **architect** role

Feedback format matches the reviewer role:

```
**Severity:** [required | suggestion | question]
**Journey step:** [where in the flow]
**Problem:** [what the user experiences]
**Suggestion:** [how to fix]
```
